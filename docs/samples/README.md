# Образцы файлов обмена с 1С

Четыре файла CommerceML 2 под данные, которые заливает `backend/database/seed.py`.
Ими можно проверить обмен, не дожидаясь настоящей выгрузки из 1С.

Формат и правила — [docs/api.md §6.8](../api.md).

## Как проверять

Поднимите стенд и войдите **администратором** — у него есть право менять и
справочник, и остатки:

```
cd backend && make up
cd desktop && uv run main.py
```

Логин `admin`, пароль — `SEED_PASSWORD` из `backend/.env`.

Справочник общий для всех складов, а остатки грузятся **на склад того, кто
нажал кнопку**. У `admin` это Склад №1, поэтому все числа ниже — про него.
Войдёте другой учётной записью — остатки лягут на её склад, и «создано»
окажется там, где у Склада №1 стоит «без изменений».

Порядок важен: номенклатуру загружают до остатков, иначе позициям не с чем
сопоставляться. Цифры ниже верны для **свежей базы** (`make reset`); повторная
загрузка того же файла даст те же строки в «без изменений» — это и есть
проверка идемпотентности.

## Файлы

### `1c-import.xml` → Справочник · Импорт

Четыре позиции, по одной на каждый исход загрузки.

| Позиция | Что в файле | Итог |
|---|---|---|
| `ТМЦ-00512` Труба | всё как в базе | без изменений |
| `ТМЦ-00421` Болт | наименование и вес изменены | обновлено |
| `ТМЦ-02001` Подшипник | новая | создано |
| `ТМЦ-02002` Ремень | новая | создано |

```
создано 2 · обновлено 1 · без изменений 1 · пропущено 0
```

### `1c-import-problems.xml` → Справочник · Импорт

Намеренно испорченные позиции — посмотреть, как выглядит отчёт. Одна годная
позиция загрузится, пять будут пропущены с объяснением:

```
создано 1 · обновлено 0 · без изменений 0 · пропущено 5

  2. ТМЦ-02004 — нет наименования
  3. ТМЦ-02005 — нет базовой единицы измерения
  4. позиция 4 — нет ни кода 1С, ни артикула — сопоставить не с чем
  5. ТМЦ-02006 — помечена на удаление в 1С
  6. ТМЦ-ЧУЖОЙ — артикул 100421 занят позицией с другим кодом 1С
                 (ТМЦ-00421) — это разные товары
```

Последняя строка — не придирка. Артикул в выгрузках 1С не уникален: в её
собственной демо-выгрузке один артикул носят два разных товара. Сопоставить их
по артикулу значило бы слить две позиции в одну и потерять остаток.

### `1c-offers.xml` → Остатки · Импорт

Инвентаризация: количество из файла **становится** остатком, разница уходит
движением «пересчёт» с пометкой «Импорт из 1С». Видно в карточке товара.

| Позиция | Было на Складе №1 | В файле | Итог |
|---|---|---|---|
| `ТМЦ-00421` Болт | 800 | 800 | без изменений |
| `ТМЦ-00477` Уголок | 40 | 36 | обновлено, движение −4 |
| `ТМЦ-00512` Труба | строки нет | 95.5 | создано |
| `ТМЦ-01187` Подшипник | 12 | 8 + 4 по складам | без изменений |

```
создано 1 · обновлено 1 · без изменений 2 · пропущено 0
```

Последняя позиция записана так, как это делает 1С:УТ 11 — остаток атрибутом
`Склад/@КоличествоНаСкладе`, по строке на склад. Склады из файла складываются
в одно число: на какой наш склад оно ляжет, решает учётная запись, а не файл.

### `1c-offers-variants.xml` → Остатки · Импорт

Два варианта одной трубы составным идентификатором `ТМЦ-00512#вариант-…` — так
1С выгружает размеры и цвета. В нашем справочнике им соответствует одна
позиция, поэтому количества складываются: 30 + 12.5 = **42.5**. Третья позиция
в справочнике отсутствует и будет пропущена.

```
создано 0 · обновлено 1 · без изменений 0 · пропущено 1

  3. ТМЦ-НЕИЗВЕСТНЫЙ — позиции нет в справочнике — сначала загрузите номенклатуру
```

Этот пропуск стоит прочитать внимательно: он означает, что файл остатков
применили без файла номенклатуры. Без такого сообщения загрузка отчиталась бы
об успехе, оставив половину склада нетронутой.

## Выгрузка

Кнопка «Экспорт для 1С» в том же разделе отдаёт `import.xml` и `offers.xml`
того же формата. Самая быстрая проверка: выгрузить и тут же загрузить обратно —
всё должно попасть в «без изменений», ни одного нового движения.

**Цен в выгрузке нет.** ProЗапас их не ведёт, а нулевая цена в обмене
означала бы «товар стоит ноль» и обнулила бы прайс на стороне 1С.

## Вернуть базу к исходному

```
cd backend && make reset
```

Сносит базу и собирает заново из миграций и сида.
